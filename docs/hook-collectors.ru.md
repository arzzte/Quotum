# Локальные hook-коллекторы

Hook заменяет штатный коллектор подписки локальной программой пользователя. Она может
измерять несколько аккаунтов одного провайдера на одном устройстве. Quotum сохраняет
ответственность за псевдонимы, расписание каждого аккаунта, duty, политику участия,
доставку и повторы. Не нужны отдельный токен хаба, виртуальные устройства, служба или
собственная реализация ingest: используется существующее подключение `quotum connect`.
Hook не меняет обнаружение клиентов, учёт их работы и сведения об их текущем входе.

## Настройка

```toml
[providers.claude.hook]
path = "/absolute/path/to/usage-hook"
args = []
```

Для скрипта можно явно указать интерпретатор:

```toml
[providers.claude.hook]
path = "/absolute/path/to/python3"
args = ["-I", "/absolute/path/to/usage-hook.py"]
```

Поддерживаются существующие провайдеры с клиентскими измерениями: `claude`, `codex`,
`antigravity`. Hook заменяет измерения, но не настройку клиентского `path`.
`enabled = false`, `--only` и минимальный `interval` провайдера действуют как обычно.
После изменения конфигурации перезапустите агент. `quotum --only claude --json`
перечислит и измерит аккаунты один раз; `quotum run --only claude` следует расписанию хаба.

Путь к программе должен быть абсолютным. Shell не запускается, `~` не раскрывается,
строка команды не разбирается. Аргументы передаются буквально: не более 32, каждый
до 4096 байт, без NUL. Файлы `.cmd` и `.bat` запрещены; в Windows укажите исполняемый
файл или интерпретатор. Рабочая папка нейтральная, приоритет пониженный, окружение
как у штатного клиента, без `QUOTUM_*`. Stderr отбрасывается. На каждый запуск отводится
60 секунд и 256 КиБ stdout, включая вывод без переводов строк. Нужны EOF и успешный
код завершения. При остановке, таймауте и завершении используется штатная очистка
дерева процессов.

## Контракт v1

Программа читает один JSON-запрос из stdin до EOF, печатает ровно один JSON-ответ
в stdout и завершается. Не выводите туда прогресс, секреты, пути, полные ответы
провайдера или диагностику. Версия 1 отвергает неизвестные поля. В списке не более
16 аккаунтов — это существующий лимит check-in. `provider` каждой записи должен
совпадать с настройкой. Дубликаты, включая совпадения после штатной нормализации
псевдонима, недопустимы.

### Перечисление

Запрос:

```json
{"version":1,"action":"discover"}
```

Ответ:

```json
{"version":1,"accounts":[
  {"provider":"claude","identity":{"email":"user@example.com","organization":"Example"}},
  {"provider":"claude","identity":{"email":"second@example.com","organization":"Example"}}
]}
```

Перечисление возвращает только идентичности, без окон, плана и ошибок. Оно не должно
обращаться к провайдеру или модели. Агент проверяет разрешение участия ещё до него.
Перечисление повторяется с настроенным интервалом провайдера, по умолчанию 120 секунд:
аккаунты могут появляться и исчезать без перезапуска. Расписание оставшихся аккаунтов
сохраняется. Пустой список допустим. При ошибке check-in и измерения этого списка
приостанавливаются, повтор откладывается с ограниченным backoff. Расписания аккаунтов
сохраняются до успешного перечисления; состояние удаляется только при подтверждённом
исчезновении аккаунта.

### Измерение

Quotum делает check-in для полного обнаруженного списка. Хаб выбирает аккаунты,
которые пора измерить именно этому устройству. Только они передаются программе:

```json
{"version":1,"action":"measure","accounts":[
  {"email":"user@example.com","organization":"Example"}
]}
```

Ответ:

```json
{"version":1,"accounts":[{
  "provider":"claude",
  "identity":{"email":"user@example.com","organization":"Example"},
  "plan":"max",
  "windows":[
    {"id":"session","kind":"session","minutes":300,"usedPercent":12.5,"resetsAt":"2026-10-26T23:00:00Z"},
    {"id":"weekly","kind":"weekly","minutes":10080,"usedPercent":37,"resetsAt":"2026-11-01T23:00:00Z"},
    {"id":"weekly:sonnet","kind":"weekly","minutes":10080,"label":"Sonnet","usedPercent":8}
  ]
}]}
```

Измеряйте **только запрошенные идентичности**. Другой аккаунт в ответе, в том числе
после смены учётных данных во время сбора, делает ответ недопустимым. Нужна одна запись
на запрошенный аккаунт; пропущенная запись становится ошибкой только этого аккаунта.
Порядок не важен. Ошибка одного аккаунта не требует отбрасывать успешный замер другого:

```json
{"version":1,"accounts":[{
  "provider":"claude",
  "identity":{"email":"user@example.com","organization":"Example"},
  "error":"not_logged_in"
}]}
```

Ошибки: `not_installed`, `not_logged_in`, `unsupported`, `timeout`, `invalid_output`,
`failed`. При ошибке `windows` и `plan` отсутствуют. Не добавляйте произвольный текст.
Ненулевой код завершения, таймаут, превышение вывода или недопустимый JSON становятся
ошибками всех запрошенных измерений, а не падением агента. Диагностика фиксированная:
без исходного вывода, аргументов, ошибок провайдера и сообщений парсера.

При успехе нужны 1–32 уникальных окна. `kind`: `session`, `weekly`, `other`, независимо
от id. `usedPercent` — конечное число от 0 до 100. Если есть `minutes`, оно положительное;
`resetsAt` — RFC 3339 с часовым поясом. Неизвестный сброс пропускается или равен null.
План, id и подписи — непустой текст без управляющих символов, до 120 символов; id
уникальны и после удаления пробелов по краям. План необязателен: не угадывайте его.
Первая версия передаёт процентные окна, без балансов и бесплатных сбросов.
Время наблюдения после завершения команды, свежесть из расписания и
`via = "local-hook/v1"` задаёт Quotum.

### Идентичности провайдеров

| Провайдер | `identity` | Обработка |
|---|---|---|
| Claude | `{"email":"user@example.com","organization":"Example"}` | Те же email и организация, что сообщает Claude Code; организация обязательна, но может быть пустой. |
| Codex | `{"accountId":"provider-account-id"}` | Тот же стабильный id, что возвращает штатный app-server. |
| Antigravity | `{"accountName":"work"}` | Имя подписки владельца, как штатный `providers.antigravity.account`; псевдоним провайдера не придумывается. |

Не смешивайте поля разных провайдеров. Поля идентичности ограничены 120 символами
без управляющих; пустой может быть только организация. Для Claude и Codex вызывается
та же функция псевдонима, что у штатного адаптера. Скрипт не хеширует идентичности
и не собирает ingest. Одинаковые исходные данные дают одну подписку на разных
устройствах и при разных коллекторах. Исходные идентичности провайдера для Claude
и Codex остаются в памяти и stdin/stdout программы, не попадают в spool, логи или хаб.
Заданное пользователем `accountName` Antigravity передаётся хабу в check-in и снимках
и может попасть в spool, как при штатном сборе. Для идентичности имя очищается от
пробелов по краям и приводится к нижнему регистру; смена регистра не создаёт аккаунт.
Аккаунты пула не становятся свидетельством текущего входа штатного клиента.

## Доверие и границы ошибок

Включая hook, вы запускаете **свой код с правами своего пользователя**. Это не песочница
и не система подписанных плагинов. Защитите программу, скрипт, интерпретатор и родительские
папки от чужой записи. Предпочитайте изолированный режим интерпретатора, абсолютные пути
и не передавайте секреты в аргументах. Лимиты защищают Quotum, но не остальную систему
от вредоносного hook. Унаследованное окружение без переменных Quotum может содержать
ваши секреты. Доступ к учётным данным и сети контролирует скрипт. Сам Quotum не открывает
файлы секретов провайдера, не обновляет токены, не обращается к API провайдеров и не делает
запросов к модели. Hook тоже не должен делать запросы к модели. Хранение секретов
и доступ к провайдеру принадлежат вашему скрипту, вне продукта и контракта Quotum.

В фоновом режиме аккаунты сохраняют отдельные duty, команды, epochs, свежесть,
backoff и fallback при недоступном хабе через существующие расписание и доставку.
Перечисление само по себе не создаёт подписку на хабе: это делают обычные check-in
и принятые измерения. Ошибки перечисления без аккаунта остаются личной диагностикой
устройства. Изменения хаба, базы и ingest-протокола не нужны.
